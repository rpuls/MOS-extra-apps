# Epson to Paperless — technical reference

A MOS package around [`mtheuma/epson2paperless`](https://github.com/mtheuma/epson2paperless), which speaks Epson's ESC/I and ESC/I-2 scanner protocols and uploads the result to Paperless-ngx.

It is a plugin for the official `paperless-ngx` package, not a standalone app: the Paperless address arrives through a MOS connection between the two and is never asked for at install. Paperless-ngx 0.3.2 or later is required, because that is the version that publishes the capability this package consumes.

## Services

| Service | Dockerfile | Internal port | Base image |
| --- | --- | --- | --- |
| `epson2paperless` | `Dockerfile` | 3000 | `ghcr.io/mtheuma/epson2paperless`, pinned to the v0.12.0 index digest |

The package does not build the application. It pins the upstream multi-architecture image by digest and adds one layer that creates `/output` owned by the image's unprivileged `node` user, because that user cannot create a directory at the filesystem root and MOS seeds the named volume from the image.

## Environment variables

| Variable | Source | Purpose |
| --- | --- | --- |
| `HEALTH_PORT` | literal `3000` | Port for `GET /health` and `POST /scan`; must match `internalPort`. |
| `PRINTER_IP` | `${config.printerIp}` | The scanner's fixed address on the home network. |
| `PAPERLESS_URL` | the `documentArchive` connection | Base address of Paperless-ngx, `http://paperless:8000`. Written by MOS when the two apps are connected, and absent until then. |
| `PAPERLESS_TOKEN` | `${secret.paperlessToken}` | Paperless API token, minted in Paperless's own admin. |
| `SCAN_TRIGGER_TOKEN` | `${secret.scanTriggerToken}` | Generated by MOS at install. Its presence is what opens `POST /scan`; without it the path is a plain 404. |
| `SCAN_FORMAT` | `${config.scanFormat}` | `pdf` or `jpg`. Decides the format, because no panel choice reaches a triggered scan. |
| `SCAN_SIDES` | `${config.scanSides}` | `simplex` or `duplex`, same reason. Defaults to `simplex`, which every model can do. |
| `OUTPUT_DIR` | literal `/output` | Where scans are written before upload. |
| `LOG_FORMAT` | literal `json` | One record per line, so `docker logs` stays parseable. |

Upstream supports more variables than these — resolution, colour mode, post-processing, TLS pinning, timeouts. They are left at their defaults here; add them as setup fields if you need them.

## Volumes

| Volume | Mount | Contents |
| --- | --- | --- |
| `scan-output` | `/output` | Scans, written before upload. Upstream deletes each file once Paperless accepts it, and keeps it when the upload fails. |

## Endpoints

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/health` | Health endpoint. Reports when a scan was last *triggered*, not whether it succeeded. Unauthenticated. |
| `POST` | `/scan` | Starts a scan. Requires `Authorization: Bearer <SCAN_TRIGGER_TOKEN>`. Answers `202` before the scan runs, `409` while one is already running, `401` on a bad token. Optional query parameters: `format`, `sides`, `postProcess`, `colorMode`. |

Both are served on the package's public route, `ext-epson2paperless` under the suite domain.

## What this package cannot do

Upstream's primary mode is the scanner's own **Scan to Computer** panel entry. That needs two things MOS does not grant a package it has not reviewed:

- The scanner announces itself by UDP multicast on the home network, which a container on Docker's bridge network never sees. Upstream's own deployment uses host networking for exactly this reason, and `network`/`networkMode` is refused for a non-official package.
- The scan itself arrives as an inbound TCP connection from the scanner on port 2968. A package declares one `internalPort`, published to loopback and served over HTTPS by MOS; `ports` is refused, so nothing on the home network can open a connection to the app.

So the daemon runs with its discovery and its panel listener going nowhere: the destination never appears on the scanner's panel, and the log says it is waiting for a scan that cannot arrive. The triggered path is unaffected — it skips discovery entirely and connects out to the scanner, which a bridged container can do.

A restart or a stop while a scan is running loses that scan. MOS gives a container Docker's default ten seconds to shut down, which is shorter than the two minutes upstream wants for an in-flight page feed.

## Paperless

Uploads go to `POST ${PAPERLESS_URL}/api/documents/post_document/`.

The address comes from the connection. `integrations.documentArchive` accepts Paperless's `document-archive` capability and applies its `internalBaseUrl` to `PAPERLESS_URL` through the `paperlessApi` config target, which is the only environment key that target allows. Connecting also puts this container on Paperless's network, so the upload stays inside the server instead of leaving it and coming back through the suite's web server.

The token does not come from the connection, and cannot. A MOS connection can only hand over a secret MOS itself generated — the way the ONLYOFFICE JWT secret reaches Seafile — and a Paperless API token is minted inside Paperless's own database, where MOS never sees it. So it stays a setup field, and it has to exist before this app is installed: create it in Paperless under **My Profile** first.

That token is the whole of this package's access to Paperless, and it carries every right its user has — reading and deleting documents, not only adding them. Give it a Paperless user made for the scanner rather than an administrator's. Connecting puts this container on Paperless's own network — it is the plugin, so it joins rather than being joined — which means it can reach every Paperless service, the Valkey broker included; the token is what decides what it can do with the archive, but the network is shared either way. Because the network belongs to Paperless, uninstalling this package takes nothing away from it.

Until the two are connected the app has no `PAPERLESS_URL` at all. Upstream treats that as file-only mode, so a triggered scan still runs and the pages are kept in `scan-output`; nothing is filed.

## Local run (without MOS)

Upstream's own instructions are the ones to follow, including host networking, which gets the panel button working:

```sh
docker run --rm --network host \
  -e PRINTER_IP=192.0.2.58 \
  -e PAPERLESS_URL=http://paperless:8000 \
  -e PAPERLESS_TOKEN=... \
  -v epson2paperless-output:/output \
  ghcr.io/mtheuma/epson2paperless:v0.12.0
```
